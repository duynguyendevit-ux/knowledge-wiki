Unity Advanced Scripting Guide

Comprehensive reference for advanced C# design patterns and scripting techniques in Unity. Based on GameDev Beginner’s design patterns series.

1. Inheritance

What is Inheritance?

Inheritance cho phép class con (child/derived class) kế thừa functionality từ class cha (parent/base class). Điều này giúp tái sử dụng code và tạo cấu trúc phân cấp cho objects.

Key Concepts

  • Base Class: Class cha chứa shared functionality
  • Derived Class: Class con kế thừa và có thể override/extend behavior
  • Abstract Classes: Class không thể instantiate, dùng làm template
  • Virtual Methods: Methods có thể override ở class con
  • Protected: Access modifier cho phép class con truy cập

Code Example

When to Use

  • Use when: Objects có shared core behavior dựa trên “what they are”
  • Good for: Player/Enemy systems, Weapon hierarchies, Vehicle types
  • Avoid when: Relationships không rõ ràng hoặc cần multiple inheritance

Pros & Cons

Pros:

  • Tái sử dụng code hiệu quả
  • Dễ maintain shared behavior
  • Tạo cấu trúc rõ ràng

Cons:

  • Chỉ inherit từ 1 base class
  • Có thể tạo deep hierarchies phức tạp
  • Tight coupling giữa parent và child

2. Structs

What are Structs?

Structs là value types, khác với classes (reference types). Chúng được pass by value và store trên stack thay vì heap.

Key Concepts

  • Value Type: Copy toàn bộ data khi assign
  • Stack Allocation: Nhanh hơn heap, tự động cleanup
  • No Inheritance: Structs không thể inherit
  • No Null: Structs luôn có value

Code Example

When to Use

  • Use when: Small, simple data structures (<16 bytes khuyến nghị)
  • Good for: Coordinates, Colors, Stats bundles, Config data
  • Avoid when: Large data, cần inheritance, cần null checks

Structs vs Classes

StructsClasses
Value typeReference type
Stack allocationHeap allocation
Passed by valuePassed by reference
No inheritanceSupports inheritance
No nullCan be null

3. Enums

What are Enums?

Enums tạo một set các named constants. Về bản chất chúng là integers nhưng có human-readable labels.

Key Concepts

  • Named Values: Dùng names thay vì magic numbers
  • Type Safety: Compiler checks valid values
  • Underlying Type: Default là int, có thể custom
  • Flags: Multiple choice enums với bitwise operations

Code Example

When to Use

  • Use when: Limited set of known options, dropdown selections
  • Good for: States, Difficulty levels, Directions, Categories
  • Avoid when: Values cần thay đổi thường xuyên, cần store additional data

Best Practices

  • Prefix enum names với “I” nếu là interface-like
  • Luôn set explicit values nếu order có thể thay đổi
  • Dùng [System.Flags] cho multiple choice
  • Zero value nên là default/none state

4. Async / Await

What is Async?

Async/Await cho phép execute code không đồng bộ, không block main thread. Khác với Coroutines, async chạy trên background thread.

Key Concepts

  • async keyword: Đánh dấu method là asynchronous
  • await keyword: Wait for task completion
  • Task: Đại diện cho async operation
  • Non-blocking: Main thread tiếp tục chạy

Code Example

Async vs Coroutines

Async/AwaitCoroutines
Runs on background threadRuns on main thread
Survives object destructionStops when object destroyed
Can return valuesCannot return values
Needs cancellation tokensAuto-stops with object
Better for heavy operationsBetter for frame-based timing

When to Use

  • Use when: Heavy computations, loading assets, network calls
  • Good for: File I/O, API calls, scene loading
  • Avoid when: Simple delays, WebGL builds, need tight Unity integration

Best Practices

  • Luôn use try/catch/finally với cancellation
  • Cancel tasks trong OnDestroy()
  • Không reference Unity objects trong background thread
  • Task.Delay dùng milliseconds, không phải seconds

5. State Machines

What are State Machines?

State Machine quản lý behavior dựa trên current state của object. Mỗi state xử lý logic riêng và transitions.

Key Concepts

  • State: Một behavior mode cụ thể
  • Transition: Điều kiện chuyển state
  • State Controller: Quản lý current state
  • Enter/Exit: Setup và cleanup khi đổi state

Code Example (Interface-based)

When to Use

  • Use when: Clear, distinct behavioral states
  • Good for: AI behaviors, Game states, Animation controllers
  • Avoid when: States overlap significantly, need parallel behaviors

State Machines vs Behavior Trees

  • State Machines: Fixed transitions, simpler logic
  • Behavior Trees: Dynamic priority-based decisions, more complex

6. Interfaces

What are Interfaces?

Interfaces định nghĩa contract - một set of methods mà class phải implement. Cho phép treat different classes như cùng type.

Key Concepts

  • Contract: Class phải implement tất cả interface methods
  • Multiple Interfaces: Class có thể implement nhiều interfaces
  • Polymorphism: Dùng interface type thay vì concrete type
  • No Implementation: Interface chỉ declare, không implement

Code Example

When to Use

  • Use when: Nhiều different classes cần shared functionality
  • Good for: Damage systems, Interaction systems, Collectables
  • Avoid when: Chỉ có 1-2 classes, hoặc cần shared implementation

Interfaces vs Inheritance

  • Interfaces: “Can do” relationship, multiple allowed
  • Inheritance: “Is a” relationship, single parent only

7. Scriptable Objects

What are Scriptable Objects?

ScriptableObjects là data containers tồn tại như assets trong project, không phải components trên GameObjects.

Key Concepts

  • Data Assets: Store data outside scenes
  • Shared References: Multiple objects reference same asset
  • Inspector Editing: Edit values in Inspector
  • No Transform: Không attach vào GameObjects

Code Example

When to Use

  • Use when: Data needs to be shared across scenes/objects
  • Good for: Item databases, Enemy stats, Global variables, Settings
  • Avoid when: Data cần unique per instance, frequent instantiation

Best Practices

  • Organize với subfolders: [CreateAssetMenu(menuName = "Game/Items/Weapon")]
  • Use order value để sort menu items
  • Runtime changes không persist (unless saved explicitly)
  • Tốt cho data-driven design

8. Script Composition

What is Composition?

Composition xây dựng behavior từ small, reusable components thay vì large monolithic classes.

Key Concepts

  • Single Responsibility: Mỗi script làm một việc
  • Modular: Components có thể add/remove dễ dàng
  • Loose Coupling: Components không phụ thuộc lẫn nhau
  • Reusability: Dùng lại components cho nhiều objects

Code Example

When to Use

  • Use when: Functionality không fit vào clear hierarchy
  • Good for: Mixed abilities, Modular systems, Plugin-style features
  • Combine with Inheritance: Core behavior inheritance + composition cho abilities

Composition vs Inheritance

  • Composition: “Has a” relationship, flexible mixing
  • Inheritance: “Is a” relationship, fixed hierarchy

9. Singletons

What are Singletons?

Singleton là globally accessible instance, chỉ tồn tại duy nhất một instance trong scene.

Key Concepts

  • Global Access: Truy cập từ anywhere qua static reference
  • Single Instance: Chỉ một instance tồn tại
  • Persistent: Có thể persist across scenes với DontDestroyOnLoad
  • Controversial: Dễ overuse, gây tight coupling

Code Example

When to Use

  • Use when: Truly need global access, genuinely only one instance
  • Good for: Game managers, Audio managers, Save systems
  • Avoid for: Player objects, Anything có thể có multiple instances

Risks & Drawbacks

  • Global State: Khó test và debug
  • Tight Coupling: Scripts phụ thuộc vào singleton
  • Hard to Refactor: Khó thay đổi sau khi đã dùng nhiều
  • Hidden Dependencies: Không rõ script dependencies

Best Practices

  • Chỉ dùng cho game systems, không phải game objects
  • Consider Events/ScriptableObjects thay vì Singletons
  • Use Service Locator nếu có nhiều managers
  • Document clearly khi dùng singletons

10. Events & Delegates

What are Events & Delegates?

Delegates là function containers. Events là special delegates tạo observer pattern - decouple trigger từ response.

Key Concepts

  • Delegate: Function pointer, có thể hold multiple functions
  • Event: Delegate với restrictions (chỉ class owner trigger được)
  • Subscribe/Unsubscribe: Add/remove functions với += và -=
  • Multicast: Một event trigger nhiều functions

Code Example

Event Types Comparison

TypeUse CaseInspectorProsCons
DelegateFunction containersNoFlexibleCan be called externally
EventObserver patternNoSecureCode-only

UnityEventDesigner-friendlyYesVisual setupPerformance overhead

When to Use

  • Use when: Decouple trigger from response, multiple listeners
  • Good for: Game events, UI callbacks, Achievement systems
  • Avoid when: Simple one-to-one calls, performance critical loops

Best Practices

  • Luôn unsubscribe trong OnDisable/OnDestroy
  • Dùng ?.Invoke() để null-check
  • Events cho public exposure, delegates cho parameters
  • Actions cho simple events
  • UnityEvents cho designer-friendly events

Summary & Guidelines

Choosing the Right Pattern

For Object Relationships:

  • Inheritance: Core “is-a” relationships (Player is Human)
  • Composition: Mixed abilities “has-a” (Player has Health, has Movement)
  • Interfaces: Shared capabilities (IDamageable, IInteractable)

For Data Management:

  • Structs: Small value types (Vector3, Color)
  • Enums: Limited known options (States, Directions)
  • ScriptableObjects: Shared data assets (Items, Configs)

For Communication:

  • Events: Decoupled communication
  • Delegates: Function parameters, callbacks
  • Singletons: Global access (use sparingly!)

For State Management:

  • State Machines: Clear distinct states
  • Enums: Simple state tracking

For Async Operations:

  • Async/Await: Heavy operations, I/O
  • Coroutines: Frame-based timing

Best Practices

  1. Start Simple: Không overengineer từ đầu
  2. Refactor When Needed: Patterns xuất hiện naturally khi project grows
  3. Mix Patterns: Không exclusive - combine theo needs
  4. Document Decisions: Comment why you chose a pattern
  5. Think Long-term: Consider maintainability và scalability
